# 辩证综合

结合钢铁人（steel manning）的黑格尔辩证法，构建最强有力的反方论点，推动向综合发展。

## 核心原则

辩证法不是为了赢。而是为了产生比单纯的正题或反题更强的立场。 fool 的工作是要把另一方的论点阐述得如此有力，以至于用户要么必须完善自己的立场，要么承认真正的权衡取舍。

## 流程

1. **重申正题** — 首先以钢铁人方式表述用户立场
2. **构建反题** — 建立最强的对立论点
3. **呈现冲突** — 展示正题和反题真正冲突的地方
4. **推动综合** — 提出一个融合两者优点的立场

## 钢铁人技术

钢铁人（steel manning）是稻草人（straw manning）的对立面。在反驳之前，先用最强的形式重述用户的立场。

### 如何进行钢铁人

| 步骤 | 动作 | 示例 |
|------|--------|---------|
| 1. 识别核心主张 | 剥离薄弱的表述 | "我们应该使用微服务" → "独立部署和扩展组件将加速团队开发速度" |
| 2. 添加最强证据 | 补充用户隐含的内容 | "...特别是考虑到4个团队在不同的发布周期上工作" |
| 3. 承认真实好处 | 指出真正好的方面 | "这将消除当前的部署队列瓶颈" |
| 4. 向用户确认 | "这样的重述准确吗？" | 确保你攻击的是真实的立场 |

### 钢铁人检查清单

- [ ] 我是否让立场更强，而不是更弱？
- [ ] 用户是否认这是他们的观点（或更好的版本）？
- [ ] 我是否包含了他们立场的最强证据？
- [ ] 我是否在攻击这个版本，而不是更容易的版本？

## 反题构建

### 技术：最强反方论点

通过以下问题构建反题："如果一个聪明、了解情况的人不同意，他们会提出什么最好的论点？"

| 反方论点来源 | 示例 |
|----------------------------|---------|
| 对立的权衡取舍 | "现在速度 vs. 后期可维护性" |
| 隐藏成本 | "迁移成本超过18个月的预计节省" |
| 解决相同问题的替代方案 | "模块化单体架构以20%的成本获得80%的收益" |
| 类似情况的前例 | "X公司尝试了，2年后又回滚了" |
| 正题不服务的利益相关者 | "初级开发人员会在额外的复杂性中挣扎"

### 归谬法（辅助技术）

将正题推向逻辑极端，以揭示其隐藏的局限性。

| 正题 | 归谬 | 揭示 |
|--------|----------|---------|
| "我们应该优化开发者体验" | "那我们就不应该发布到生产环境，因为bug伤害DX" | DX必须与交付平衡 |
| "更多测试总是更好" | "那我们应该包括getter/setter在内的100%覆盖率" | 测试的价值呈递减 |
| "我们应该快速前进" | "那就跳过代码审查和测试" | 速度有质量底线 |

谨慎使用。归谬法强调的是原则的边界，而不是其无效性。

## 综合模式

在呈现正题和反题后，使用以下模式之一提出综合。

### 1. 条件性综合

"当条件A成立时，X为真；当条件B成立时，Y为真。"

示例："微服务适合支付服务（独立扩展，合规边界），但管理仪表盘应该保留在单体架构中（流量小，快速迭代）。"

### 2. 范围分区

"在领域A应用X，在领域B应用Y。"

示例："对审计轨迹使用事件溯源（只追加，可查询历史），但对用户配置文件使用标准CRUD（简单读写）。"

### 3. 时间性综合

"从X开始，当触发事件Z发生时迁移到Y。"

示例："从单体架构开始，当团队规模超过3个小组或部署频率出现周级别冲突时提取服务。"

### 4. 风险缓解综合

"继续X，但添加Y的保障措施。"

示例："采用新框架，但保留抽象层，以便在2个冲刺内可以切换回来。"

### 5. 混合提取

"取双方最强大的元素。"

示例："使用微服务部署模式（独立容器），但保留共享数据库和模式所有权（避免分布式数据复杂性）。"

## 置信度评估

评估综合结果。

| 级别 | 含义 | 行动 |
|-------|---------|--------|
| **高** | 综合明显强于任一方单独 | 继续使用综合 |
| **中** | 综合合理但未经检验 | 识别风险最大的假设，建议进行实验 |
| **低** | 双方都有强烈且不可调和的主张 | 指出真正的权衡取舍；让用户根据优先级决定 |
| **转向** | 反题比正题更强 | 建议用户重新考虑原始立场 |

## 反模式

| 反模式 | 问题 | 修复 |
|-------------|---------|-----|
| 虚假综合 | "都做！"而没有解决张力 | 指出正在解决的具体权衡取舍 |
| 虚弱反题 | 反方论点是稻草人 | 对反方也应用钢铁人技术 |
| 正题偏见 | 综合可疑地接近原始立场 | 检查是否真正参与了反方 |
| 复杂性蔓延 | 综合比原始方案更复杂 | 更简单的综合通常更好 |
| 和稀泥 | "看情况"而没有说明看什么情况 | 指出每条路径的确切条件 |
