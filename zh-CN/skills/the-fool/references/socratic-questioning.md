# 苏格拉底式提问

通过结构化问题框架揭示假设并加深理解。

## 核心原则

苏格拉底式提问不争论。它提问。目标是通过浮现用户未审视的内容，帮助他们发现自身推理中的漏洞。每个问题都应该创造一个"我没想到这一点"的时刻。

## 问题类别

### 1. 定义性问题

挑战模糊或过载的术语。

| 模式 | 示例 |
|---------|---------|
| "当你说X时，具体指什么？" | "当你说'可扩展'时，是指10倍用户还是1000倍？" |
| "如何向不了解的人定义X？" | "如何向非工程师解释'实时'？" |
| "是否有情况下X有不同的含义？" | "API响应和批处理的'快速'意思相同吗？" |

### 2. 证据性问题

探究信念的基础。

| 模式 | 示例 |
|---------|---------|
| "什么证据支持这个？" | "什么数据显示用户真正需要这个功能？" |
| "你怎么知道X为真？" | "你怎么知道当前系统无法处理负载？" |
| "什么会让你改变想法？" | "什么指标会让你相信这个方法是错的？" |
| "这是基于数据还是直觉？" | "'用户讨厌当前流程'的说法来自研究还是假设？" |

### 3. 逻辑性问题

测试推理链。

| 模式 | 示例 |
|---------|---------|
| "X必然导致Y吗？" | "添加缓存必然改善用户体验吗？" |
| "什么假设连接X和Y？" | "什么必须为真才能让微服务提升速度？" |
| "相反情况也可能为真吗？" | "在这种情况下，单体架构实际上可能发布更快？" |
| "你把相关性和因果性混淆了吗？" | "是重构导致了改进，还是新雇员？" |

### 4. 视角转换问题

强制考虑其他观点。

| 模式 | 示例 |
|---------|---------|
| "[利益相关者]会如何看待这个？" | "值班的工程师如何看待这个架构？" |
| "怀疑者会说什么？" | "喜欢简单性的资深工程师会说什么？" |
| "2年后这是什么样子？" | "当团队规模翻倍时，这个抽象还有意义吗？" |
| "如果这成功了，谁会失去？" | "如果我们采用这个供应商，我们会放弃什么能力？" |

### 5. 后果性问题

追踪影响。

| 模式 | 示例 |
|---------|---------|
| "接下来会发生什么？" | "我们迁移后，第一件出问题的事是什么？" |
| "第二阶效应是什么？" | "如果我们雇佣承包商来加速，团队知识会发生什么？" |
| "错误的代价是什么？" | "如果这个假设错误，恢复有多困难？" |
| "什么之后会变得更难？" | "如果我们选择这个模式，什么未来功能会变得困难？" |

## 假设检测信号

注意隐藏假设的语言。

| 信号短语 | 隐藏的假设 |
|---------------|-------------------|
| "显然..." | 说话者没有质疑这个 |
| "大家都知道..." | 共识未经验证 |
| "这只是有道理..." | 推理链没有被阐明 |
| "我们总是..." | 假设历史模式是最优的 |
| "没有其他方法..." | 替代方案未被探索 |
| "这很简单..." | 复杂性被低估 |
| "用户想要..." | 用户研究可能缺失或过时 |
| "标准方法是..." | 约定未在这个情境中得到验证 |

## 领域适配问题库

### 技术决策

- 你在优化什么？你确定这是正确的维度吗？
- 测试核心假设的最简单版本是什么？
- 你把什么约束当作固定的，实际上它可能是有弹性的？
- 如果必须在一周内发布，你会如何构建这个？
- 最难后期变更的是什么？

### 业务决策

- 这个决策的客户是谁？你确定吗？
- 什么会让这个投资在事后看起来是糟糕的？
- 这与什么都不做相比如何？
- 这个选择的机会成本是什么？
- 如果竞争对手做了相反的选择，你会担心吗？

### 战略决策

- 什么必须为真才能让这个策略生效？
- 这些假设中你最不确信的是哪个？
- 测试风险最大假设的最快方法是什么？
- 在为时已晚之前，你如何知道这在失败？
- 如果这不奏效，退出策略是什么？
