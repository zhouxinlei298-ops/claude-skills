# 模式选择指南

当用户选择"由你决定"或自动推荐时，如何推荐合适的推理模式。

## 信号到模式的映射

分析用户的语言和上下文，以确定最适合的模式。

| 用户信号 | 推荐模式 | 理由 |
|-------------|-----------------|-----------|
| "这是正确的方法吗？" | 苏格拉底式提问 | 探索假设，尚未承诺 |
| "我即将决定采用X" | 辩证综合 | 在承诺前需要最强有力的反方论点 |
| "可能出错的地方有哪些？" | 事前分析 | 明确询问失败模式 |
| "这安全吗？" | 红队 | 安全和对抗性表述 |
| "数据显示..." | 证据审计 | 基于证据的主张需要证伪 |
| "大家都认为..." | 苏格拉底式提问 | 共识信号未经检验的假设 |
| "我们选择了X而不是Y" | 辩证综合 | 权衡决策受益于最强的反对意见 |
| "这肯定会成功" | 事前分析 | 过度自信表明需要想象失败 |
| "绝不会有人..." | 红队 | 对对手行为的假设 |
| "研究表明..." | 证据审计 | 引用的证据需要质量评估 |

## 决策类型映射

| 决策类型 | 主要模式 | 辅助模式 |
|---------------|-------------|----------------|
| 技术选择 | 辩证综合 | 事前分析 |
| 架构决策 | 事前分析 | 红队 |
| 商业策略 | 辩证综合 | 证据审计 |
| 安全设计 | 红队 | 事前分析 |
| 数据驱动的结论 | 证据审计 | 苏格拉底式提问 |
| 流程/工作流设计 | 事前分析 | 苏格拉底式提问 |
| 招聘/团队决策 | 苏格拉第式提问 | 辩证综合 |
| 供应商选择 | 事前分析 | 辩证综合 |
| 权衡解决 | 辩证综合 | 苏格拉底式提问 |
| 风险评估 | 红队 | 事前分析 |

## 领域映射

| 领域 | 默认模式 | 原因 |
|--------|-------------|-----|
| 安全 | 红队 | 对抗性思维是该领域的固有特性 |
| 基础设施 | 事前分析 | 失败模式是主要关注点 |
| 数据/分析 | 证据审计 | 主张需要证据审查 |
| 产品/UX | 苏格拉底式提问 | 关于用户的假设需要浮现 |
| 商业 | 辩证综合 | 策略受益于最强的反对意见 |
| 架构 | 事前分析 | 系统在集成点失败 |
| 法律/合规 | 证据审计 | 主张必须经受住审查 |

## 多模式序列

有些情况适合按顺序运行2个模式。

### 推荐序列

| 序列 | 何时使用 |
|----------|-------------|
| 苏格拉底式 → 辩证 | 用户有未经检验的想法。先浮现假设，然后提出反方论点。 |
| 事前分析 → 红队 | 高风险系统发布。先发现内部故障，再找外部攻击。 |
| 证据审计 → 苏格拉底式 | 数据驱动的提案。审计证据，然后质疑解读。 |
| 辩证 → 事前分析 | 战略决策。先提出反方，然后压力测试幸存下来的立场。 |

### 何时建议多模式

当以下情况时建议二次处理：
- 第一个模式揭示了用户未考虑的风险类别
- 正题在第一次挑战后基本完整（可能需要更严格的测试）
- 领域跨越两个映射类别（例如安全架构决策）

### 何时不要建议多模式

- 用户的问题狭窄且具体
- 第一个模式已经显现了可行的改变
- 用户表示想继续前进

## 自动推荐格式

呈现推荐时，使用这个结构：

```
Based on [specific context signal], I recommend **[Mode Name]** because [1-sentence rationale].

[If a secondary mode is relevant:]
After that, a follow-up with **[Secondary Mode]** would [1-sentence benefit].
```

然后用 `AskUserQuestion` 确认：
- 选项1：推荐的模式（带"推荐"标签）
- 选项2：如果有用，提供辅助模式
- 选项3："让我选" — 返回完整模式选择

## 边缘情况

- **模糊的上下文**：默认使用苏格拉底式提问 — 它浮现重要内容
- **多个关注点**：推荐事前分析 — 它自然覆盖广度
- **用户情绪化/沮丧**：默认使用辩证综合 — 在挑战前先以钢铁人方式确认他们的立场
- **技术vs业务分歧**：让模式匹配用户强调的一方
