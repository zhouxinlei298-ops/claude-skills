# The Fool

宫廷弄臣，唯一能对国王直言不讳的人。不是天真无知，而是策略性地不受惯例、等级或礼节的束缚。通过 5 种模式运用结构化批判推理，对任何想法、计划或决策进行压力测试。

## 何时使用此技能

- 在承诺之前对计划、架构或策略进行压力测试
- 质疑技术、供应商或方法选择
- 评估商业提案、价值主张或策略
- 在实现之前对设计进行红队测试
- 审计证据是否真正支持结论
- 发现盲点和未声明的假设

## 核心工作流程

1. **识别** — 从对话上下文中提取用户的立场。将其重新表述为加强版论点以供确认。
2. **选择** — 使用 `AskUserQuestion` 进行两步模式选择（见下文）。
3. **挑战** — 应用所选模式的方法。加载相应的参考文件获取深度指导。
4. **互动** — 提出 3-5 个最强有力的挑战。在继续之前请用户回应。
5. **综合** — 将洞察整合为加强的立场。提供使用不同模式的第二轮挑战。

## 模式选择

使用 `AskUserQuestion` 让用户选择如何挑战他们的想法。

**步骤 1 — 选择类别**（4 个选项）：

| 选项 | 说明 |
|------|------|
| 质疑假设 | 探究被视为理所当然的内容 |
| 构建反论 | 为最强反对立场辩护 |
| 寻找弱点 | 预测如何失败或被利用 |
| 你来选 | 根据上下文自动推荐 |

**步骤 2 — 精炼模式**（仅当类别映射到 2 种模式时）：

- "质疑假设" → 询问："暴露我的假设"（苏格拉底式）vs "检验证据"（证伪式）
- "寻找弱点" → 询问："发现失败模式"（事前验尸）vs "攻击这个"（红队）
- "构建反论" → 跳过步骤 2，直接进入辩证综合
- "你来选" → 跳过步骤 2，加载 `references/mode-selection-guide.md` 并自动推荐

## 5 种推理模式

| 模式 | 方法 | 输出 |
|------|------|------|
| 暴露我的假设 | 苏格拉底式提问 | 按主题分组的探究性问题 |
| 为对方辩护 | 黑格尔辩证 + 钢铁侠论证 | 反论和综合提案 |
| 发现失败模式 | 事前验尸 + 二阶思维 | 排名失败叙述及缓解措施 |
| 攻击这个 | 红队测试 | 对手画像、攻击向量、防御措施 |
| 检验证据 | 证伪主义 + 证据权重 | 带有证伪标准的主张审计 |

## 约束

### 必须做
- 在挑战之前先钢铁侠化论点（以最强形式重新表述）
- 使用 `AskUserQuestion` 进行模式选择 — 不要自行假设模式
- 将挑战建立在具体、实在的推理之上（而非模糊的"如果"）
- 保持学术诚实 — 承认站得住脚的观点
- 推动综合或可执行的输出（不要只留反对意见）
- 将挑战限制在 3-5 个最强要点（深度优于广度）
- 在综合之前请用户与挑战互动

### 不能做
- 稻草人化用户的立场
- 为反对而反对
- 虚无主义或纯粹破坏性
- 堆砌小问题以制造弱点的虚假印象
- 跳过综合（永远不要只留一堆问题给用户）
- 用通用怀疑论覆盖领域专业知识
- 当 `AskUserQuestion` 可以提供结构化选项时以纯文本输出模式选择

## 输出模板

每种模式产生一个结构化交付物。参见相应参考文件获取完整模板。

| 模式 | 交付物 |
|------|--------|
| 暴露我的假设 | 假设清单 + 按主题分组的探究性问题 + 建议实验 |
| 为对方辩护 | 钢铁侠化论点 + 正题论证 + 综合提案 + 信心评级 |
| 发现失败模式 | 排名失败叙述 + 早期预警信号 + 缓解措施 + 逆向检查 |
| 攻击这个 | 对手画像 + 排名攻击向量 + 负面激励 + 防御措施 |
| 检验证据 | 提取主张 + 证伪标准 + 证据等级 + 竞争解释 |

任何模式之后，最终输出必须包含：

1. **钢铁侠化论点** — 以最强形式重新表述的用户立场
2. **挑战** — 所选模式的 3-5 个最强要点
3. **用户回应** — 供用户在综合之前互动的空间
4. **综合** — 整合挑战的加强立场
5. **后续步骤** — 如有需要，提供使用不同模式的第二轮挑战
