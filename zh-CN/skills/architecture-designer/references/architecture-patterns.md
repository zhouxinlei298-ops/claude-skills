# 架构模式

## 模式对比

| 模式 | 最佳用途 | 团队规模 | 权衡 |
|------|----------|----------|------|
| **单体架构** | 简单领域，小团队 | 1-10 | 部署简单；部分扩展困难 |
| **模块化单体** | 复杂度增长中 | 5-20 | 模块边界；仍然是单体部署 |
| **微服务** | 复杂领域，大型组织 | 20+ | 独立扩展；操作复杂度 |
| **无服务器** | 可变负载，事件驱动 | 任何 | 自动扩展；冷启动，供应商锁定 |
| **事件驱动** | 异步处理 | 10+ | 松耦合；调试复杂度 |

## 单体架构

```
┌─────────────────────────────────────┐
│            Application              │
│  ┌─────┐  ┌─────┐  ┌─────┐         │
│  │Users│  │Orders│ │Products│       │
│  └─────┘  └─────┘  └─────┘         │
│  └──────────┬──────────────┘        │
│          Database                    │
└─────────────────────────────────────┘
```

**使用时机**：
- 开始新项目
- 小团队（< 10 名开发者）
- 简单领域
- 需要快速迭代

**优点**：部署简单，调试容易，无网络延迟
**缺点**：独立扩展困难，技术锁定，部署风险

## 微服务

```
┌──────────┐  ┌──────────┐  ┌──────────┐
│  Users   │  │  Orders  │  │ Products │
│ Service  │  │ Service  │  │ Service  │
└────┬─────┘  └────┬─────┘  └────┬─────┘
     │             │             │
┌────▼────┐  ┌────▼────┐  ┌────▼────┐
│ User DB │  │Order DB │  │ Prod DB │
└─────────┘  └─────────┘  └─────────┘
```

**使用时机**：
- 大团队（20+ 名开发者）
- 有清晰边界的复杂领域
- 每个服务有不同的扩展需求
- 多语言技术需求

**优点**：独立扩展，团队自主性，故障隔离
**缺点**：分布式系统复杂度，最终一致性，操作开销

## 事件驱动

```
┌──────────┐     ┌─────────────┐     ┌──────────┐
│ Producer │────▶│ Message Bus │────▶│ Consumer │
└──────────┘     │  (Kafka)    │     └──────────┘
                 └─────────────┘
                       │
                       ▼
                 ┌──────────┐
                 │ Consumer │
                 └──────────┘
```

**使用时机**：
- 需要异步处理
- 服务间松耦合
- 事件溯源需求
- 高吞吐量消息

**优点**：服务解耦，可扩展，审计跟踪
**缺点**：最终一致性，调试复杂，消息顺序

## CQRS（命令查询职责分离）

```
┌─────────┐         ┌─────────────┐
│ Commands│────────▶│ Write Model │──┐
└─────────┘         └─────────────┘  │
                                     ▼
                              ┌──────────┐
                              │  Events  │
                              └──────────┘
                                     │
┌─────────┐         ┌─────────────┐  │
│ Queries │◀────────│ Read Model  │◀─┘
└─────────┘         └─────────────┘
```

**使用时机**：
- 读写比例严重不平衡
- 复杂的读查询
- 事件溯源架构
- 不同的优化需求

## 快速参考

| 需求 | 推荐模式 |
|------|----------|
| 简单 CRUD 应用 | 单体架构 |
| 快速发展的初创公司 | 模块化单体 |
| 企业规模 | 微服务 |
| 可变负载 | 无服务器 |
| 异步处理 | 事件驱动 |
| 读密集型 | CQRS |
