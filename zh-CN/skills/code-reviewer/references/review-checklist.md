# 审查清单

## 综合审查清单

| 类别 | 关键问题 |
|------|----------|
| **设计** | 是否符合现有模式？抽象级别是否合适？ |
| **逻辑** | 边界情况是否处理？是否存在竞态条件？是否有 null 检查？ |
| **安全** | 输入是否验证？认证是否检查？密钥是否安全？ |
| **性能** | 是否存在 N+1 查询？是否有内存泄漏？是否需要缓存？ |
| **测试** | 覆盖率是否充足？边界情况是否测试？Mock 是否合适？ |
| **命名** | 是否清晰、一致、揭示意图？ |
| **错误处理** | 错误是否捕获？消息是否有意义？是否记录日志？ |
| **文档** | 公共 API 是否文档化？复杂逻辑是否有解释？ |

## 审查流程

### 1. 上下文（5 分钟）
- [ ] 阅读 PR 描述
- [ ] 理解要解决的问题
- [ ] 检查关联的 Issue/工单
- [ ] 记录预期变更

### 2. 结构（10 分钟）
- [ ] 审查文件组织
- [ ] 检查架构契合度
- [ ] 验证使用的设计模式
- [ ] 记录任何破坏性变更

### 3. 代码细节（20 分钟）
- [ ] 审查逻辑正确性
- [ ] 检查边界情况
- [ ] 验证错误处理
- [ ] 查找安全问题
- [ ] 检查性能问题
- [ ] 审查命名清晰度

### 4. 测试（10 分钟）
- [ ] 验证测试覆盖率
- [ ] 检查测试质量
- [ ] 查找边界情况测试
- [ ] 确保 Mock 合适

### 5. 最终检查（5 分钟）
- [ ] 记录优秀模式
- [ ] 按优先级排列反馈
- [ ] 编写总结

## 类别深入

### 设计问题
- 这个变更是否属于这个文件/模块？
- 抽象级别是否合适？
- 能否更简单？
- 是否遵循现有模式？
- 是否可扩展而无需修改？

### 逻辑问题
- null/undefined 输入会怎样？
- 边界条件是否处理？
- 是否可能存在竞态条件？
- 操作顺序是否正确？
- 所有代码路径是否都测试了？

### 安全问题
- 所有用户输入是否都验证了？
- SQL 查询是否参数化？
- 输出是否正确编码？
- 密钥是否安全处理？
- 认证是否检查？
- 授权是否强制执行？

### 性能问题
- 是否存在 N+1 查询模式？
- 数据获取是否高效？
- 昂贵的操作是否缓存？
- 是否可能导致内存泄漏？
- 是否实现了分页？

## 快速参考

| 审查重点 | 时间占比 |
|----------|----------|
| 上下文和 PR 描述 | 10% |
| 架构和设计 | 20% |
| 代码逻辑和细节 | 40% |
| 测试和覆盖率 | 20% |
| 最终审查和总结 | 10% |
