# 颜色调色板与品牌风格

**这是所有颜色和品牌特定样式的事实来源。**
要为不同的视觉身份定制图表，请编辑此文件。技能中的其他内容应保持通用和语义化。

此调色板专为以下用途优化：
- 温暖的编辑型技术博客图表
- 低密度解释性流程图
- 带有柔和分组的架构图
- 克制的对比图表
- 大标题、文章嵌入式视觉图

它**不**适用于仪表板、霓虹 UI 或高饱和度信息图。

---

## 核心风格原则

1. **颜色编码含义，而非装饰。**
2. **画布的大部分应保持中性。**
3. **强调色应稀疏且具有语义。**
4. **描边始终比填充深。**
5. **字体排版和间距比颜色更能体现层次。**
6. **优先使用平静的编辑型对比，而非鲜艳的 UI 对比。**
7. **默认不使用阴影和渐变。**

---

## 形状颜色（语义）

颜色编码含义，而非装饰。每个语义目的都有一个填充/描边对。

| 语义目的 | 填充色 | 描边色 |
|---------|--------|--------|
| 主要/中性 | #E6E2DA | #8C867F |
| 次要/上下文 | #EAF4FB | #6FA8D6 |
| 第三层/控制 | #EEEAF9 | #9A90D6 |
| 起始/触发 | #F8E9E1 | #D88966 |
| 结束/成功 | #CFE8D7 | #71AE88 |
| 警告/重置 | #F3E4DA | #C88E6A |
| 决策 | #E6D7B4 | #BFA777 |
| AI/LLM | #D7E6DC | #7FB08F |
| 非活动/已禁用 | #EFECE6 | #B4AEA6 |
| 错误 | #F8DFDA | #D96B63 |

**规则**：始终将较深的描边与较浅的填充配对以形成对比。

### 语义解释

- **主要/中性**：默认块、通用系统组件、标准容器
- **次要/上下文**：文件、技能、工具、文档、检索的上下文、存储类资源
- **第三层/控制**：路由器、内存、评估器、聚合器、编排、策略层
- **起始/触发**：用户输入、提示输入、外部触发、人工干预
- **结束/成功**：已验证结果、完成输出、已接受答案、成功状态
- **警告/重置**：重试、重置、重新进入、中断、谨慎、手动引导
- **决策**：分支点、过滤器、审批逻辑、是/否门
- **AI/LLM**：模型调用、代理工作者、活动执行阶段、推理阶段
- **非活动/已禁用**：可选项目、淡化元素、不可用或未来元素
- **错误**：失败、阻塞执行、无效状态、拒绝结果、拒绝路径

## 文本颜色（层次）

使用自由浮动文本的颜色来创建视觉层次，而无需额外的容器。

| 级别 | 颜色 | 用于 |
|------|------|------|
| 标题 | #1F1F1C | 主图表标题 |
| 副标题 | #5F5A54 | 章节标题、面板标题 |
| 正文/详情 | #4F4A44 | 标签、注释、辅助文本 |
| 淡化/支持 | #7A756E | 次要注释、非主要标签 |
| 浅填充上 | #2D2B28 | 大多数框和面板内的文本 |
| 深填充上 | #FAF8F4 | 仅限罕见使用；默认避免深填充 |

### 文本层次规则

- 仅对单个主标题使用**标题**。
- 对章节名称、面板标签和主要分组标题使用**副标题**。
- 对节点标签、箭头、注释和支持性说明使用**正文/详情**。
- 对可选字幕或低优先级标签使用**淡化/支持**。
- 优先使用自由浮动文本，而不是不必要的容器。

### 证据规则

- 仅在具体示例能改善理解时才使用证据工件。
- 不要使证据工件成为视觉上最主导的元素，除非图表明确是证据驱动的。

- 避免嵌套容器深度超过 3 层。
- 大多数图表应该有 1 个外层分组级别和 0-2 个内层分组级别。

## 连接器样式

| 连接器类型 | 颜色 | 宽度 | 模式 | 箭头 | 用于 |
|------------|------|------|------|------|------|
| 主要流程 | #7A756E | 1.8 | 实线 | 开放，大小 14 | 主要处理路径 |
| 可选流程 | #9A948C | 1.6 | 虚线 | 开放，大小 14 | 可选/推断路径 |
| 反馈循环 | #8E8982 | 1.8 | 实线 | 开放，大小 14 | 重试/迭代循环 |
| 人工干预 | #D88966 | 1.8 | 虚线 | 开放，大小 14 | 人工中断/引导 |
| 上下文链接 | #7FB08F | 1.8 | 实线 | 开放，大小 14 | 上下文注入/支持流程 |
| 错误路径 | #D96B63 | 1.8 | 实线或虚线 | 开放，大小 14 | 失败/阻塞路径 |

**箭头规则**：所有连接器都使用 `endArrow=open;endSize=14;`——这是 Anthropic 博客图表最具辨识度的视觉元素。开放式 V 形箭头（不是实心三角形）赋予图表编辑、出版质量的外观。永远不要使用实心/块状箭头。

### 连接器规则

- 在架构图中优先使用**正交连接器**。
- 在工作流图中优先使用**直线或轻微正交的连接器**。
- 主要对反馈循环使用**弯曲连接器**。
- 谨慎使用虚线连接器；太多会使图表感觉不确定。
- 主流程应在 3 秒的查看时间内视觉上显而易见。

## 语义映射规则

将用户意图转换为样式节点时使用此映射。

- 对模型调用、代理工作者、推理阶段、执行阶段使用 **AI/LLM**。
- 对文件、文档、工具、技能、检索的上下文和系统资源使用 **次要/上下文**。
- 对路由器、内存、评估器、聚合器、控制器和编排逻辑使用 **第三层/控制**。
- 对提示、用户、中断、外部系统和手动输入使用 **起始/触发**。
- 对已验证输出、最终答案、已完成作业和已接受结果使用 **结束/成功**。
- 对重试路径、重置、重新进入点和谨慎状态使用 **警告/重置**。
- 仅对分支点、门、审批、过滤器是/否逻辑使用 **决策**。
- 对占位符、禁用功能、可选未来节点和淡化元素使用 **非活动/已禁用**。
- 对阻塞执行、拒绝操作、无效状态、验证失败和硬停止使用 **错误**。

## 图表类型默认值

### 工作流图
- 背景：画布背景
- 节点：AI/LLM、起始/触发、结束/成功、决策（根据需要）
- 连接器：主要流程 + 可选反馈循环
- 布局：干净的线性或柔和分支
- 优先强调：流程清晰度

### 架构图
- 背景：带有面板分组的画布背景
- 节点：主要/中性 + 次要/上下文 + 第三层/控制
- 连接器：正交
- 布局：分组系统和接口
- 优先强调：包含和交互

### 对比图
- 背景：两个或更多大的中性面板
- 节点：柔和语义填充
- 连接器：最少
- 布局：镜像或并排
- 优先强调：结构对比，而非颜色

### 图表图
- 背景：温暖中性
- 条/系列：使用中性 + 1-2 个克制的强调色
- 网格线：非常浅的中性描边
- 优先强调：直接值比较，低混乱

### 编辑海报图
- 大标题、稀疏元素、超大留白
- 最少箭头
- 强烈的构图平衡
- 仅一个主导思想

## 非目标

除非用户明确要求，否则避免这些：
- 饱和的品牌色
- 投影
- 光泽 UI 处理
- 渐变
- 重图标装饰
- 密集图例
- 一个图表中超过 4 种语义强调色
- 仪表板美学

---

## 回退规则

如果语义含义不清楚：
1. 默认使用 **主要/中性**
2. 对被动信息对象使用 **次要/上下文**
3. 对活动计算步骤使用 **AI/LLM**
4. 对路由或类似内存的逻辑使用 **第三层/控制**
5. 仅当某物真正启动流程时才使用 **起始/触发**

如果颜色太多：
- 将低优先级语义合并到 **主要/中性**
- 仅保留 2-3 个最有意义的强调类别

如果图表感觉太忙：
- 在移除间距之前先移除容器
- 在减少颜色之前先减少连接器数量
- 将次要标签降级为淡化文本

## XML 实现注意事项

使用这些颜色值时，请注意以下 XML 实现细节：

### 属性值必须用引号括起

所有属性值，包括数字类型，都必须用引号括起：

```xml
<!-- ✅ 正确 -->
<mxGeometry x="20" y="20" width="1614" height="1000"/>
<arcSize value="10"/>

<!-- ❌ 错误 -->
<mxGeometry x=20 y=20 width=1614 height=1000/>
<arcSize value=10/>
```

### value 属性中的 HTML 转义

当 value 属性包含 HTML 标签时，需要转义特殊字符：

```xml
<!-- 需要转义的字符 -->
&lt;    → <
&gt;    → >
&amp;   → &
&quot;  → "
&#10;  → 换行

<!-- 示例 -->
<mxCell value="&lt;font style=&quot;font-size: 18px;&quot;&gt;标题&lt;/font&gt;"/>
```

### 颜色值格式

颜色值可以使用十六进制格式，不需要引号（因为它们在 style 字符串内）：

```xml
<!-- ✅ 正确 -->
<fillColor=#E6E2DA/>

<!-- ❌ 错误 -->
<fillColor="#E6E2DA"/>
```

但整个 style 字符串需要用引号括起：

```xml
<!-- ✅ 正确 -->
<mxCell style="fillColor=#E6E2DA;strokeColor=#8C867F;"/>

<!-- ❌ 错误 -->
<mxCell style=fillColor=#E6E2DA;strokeColor=#8C867F;/>
```

### 避免 value 内容过于复杂

不要在 value 属性中放入大量代码或复杂内容，这容易导致解析错误。建议将详细内容放在单独的节点中。

```xml
<!-- ❌ 不推荐 -->
<mxCell value="function example() {
  const url = 'https://api.example.com';
  return fetch(url).then(r => r.json());
}"/>

<!-- ✅ 推荐 -->
<mxCell value="示例函数"/>
<!-- 在另一个节点中显示详细代码 -->
```
